# AI World 教学模型

本 Demo 让初学者从 Token 村、向量谷、注意力山脉和大模型城，走到量化矿山。地理连接表示一条学习路线，并不表示 AI 领域完整的分类或严格的先修关系。文字拆分、二维向量位置、注意力连线和续写候选均为手工教学示意，不是某个真实模型的输出。

## 内存实验的约定

所有预算和结果使用 **GiB**：1 GiB = 2³⁰ bytes。十进制 GB = 10⁹ bytes，两者不能混用。24 / 48 / 80 GiB 是抽象的可用内存预算，没有对应到具体 GPU，也不代表设备标称容量。

| 项目 | 固定值或含义 |
| --- | --- |
| 参数数目 | 为教学取整的 70,000,000,000，不是特定模型的精确参数计数 |
| 权重位数 | 每个参数平均 4 / 8 / 16 / 32 bit 的理想有效载荷 |
| 注意力结构 | Llama 3.1 70B 风格的 GQA，80 层、8 个 KV 头、每头 128 维 |
| KV 精度 | 始终 FP16，每元素 2 bytes；权重量化开关不会改变它 |
| Batch | 1 条序列，不含并发请求、beam search、共享前缀等因素 |
| Context | 已缓存的输入与生成 token 总数；2K / 8K / 32K / 128K 分别为 2048 / 8192 / 32768 / 131072 |
| 额外预留 | 人为假设的 3 GiB，用于提醒激活和运行时等开销；不是测量值、上限或安全余量保证 |

80 层、8 个 KV 头来自 [Meta 官方架构定义](https://github.com/meta-llama/llama-models/blob/main/models/sku_list.py) 的 `llama3_1_70b` 条目；每头维数由 8192 隐藏维度 / 64 注意力头 = 128 推得。这组维度只用于本实验，不适用于任意 70B 模型。公式按单序列、完整保留 K/V 的缓存计算，依据 [Hugging Face 缓存说明](https://huggingface.co/docs/transformers/cache_explanation) 的每层 K/V 张量结构推导。

```text
权重 GiB = 70 × 10⁹ × 权重 bit 数 ÷ 8 ÷ 2³⁰
KV GiB   = 2(K 和 V) × 80 层 × 8 KV 头 × 128 维 × 2 bytes × token 数 ÷ 2³⁰
合计 GiB = 权重 GiB + KV GiB + 3 GiB（假设预留）
```

| 4-bit 示例 | 权重 GiB | KV GiB | 假设预留 GiB | 合计 GiB |
| --- | ---: | ---: | ---: | ---: |
| 2K tokens | 32.60 | 0.625 | 3 | 36.22 |
| 8K tokens | 32.60 | 2.5 | 3 | 38.10 |
| 32K tokens | 32.60 | 10 | 3 | 45.60 |
| 128K tokens | 32.60 | 40 | 3 | 75.60 |

API 保留完整浮点精度，仅展示层四舍五入；是否落入预算必须比较原始合计。API 接受 1 至 131072 的整数 token 数，UI 展示上表的四个档位。

## 结果能说明什么

降低权重位数能降低这部分的理想占用；在其他约定不变时，缓存长度翻倍，KV 占用也翻倍。权重从 16-bit 降为 4-bit，权重有效载荷变为四分之一，整个推理过程的内存却不会同比变为四分之一。

实际量化格式还可能存储分组缩放因子、零点、对齐填充，并保留部分高精度权重；本公式没有单独计算这些开销。3 GiB 是单一的教学预留，并不保证涵盖它们。存储位数、计算精度和 KV 精度也是不同选择，参见 [Hugging Face bitsandbytes 文档](https://huggingface.co/docs/transformers/quantization/bitsandbytes)。

真实峰值还受到量化实现、激活、prefill 长度、算子临时缓冲、内存分配、缓存管理和其他进程影响。本实验不计算这些峰值，不支持训练、多卡切分、CPU offload、滑动窗口或量化 KV，也不预测量化后的质量、速度、吞吐、价格或硬件兼容性。模型能处理的最大上下文需由具体模型和运行配置另行确认。

界面应使用“教学估算落入预算”或“超出预算”，不要将此判断写成真实部署可运行、性能达标或不会 OOM 的承诺。
